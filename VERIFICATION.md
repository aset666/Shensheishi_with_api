## Приёмка на компьютере пользователя

1. `/start`: видны новые разделы.
2. «Известные люди: записи»: 20 карточек; 10 встроенных MP3, остальные открываются по источнику.
3. Выбрать свой созданный голос; отправить текст в «Текст на 3 языках».
4. Проверить три перевода, подтвердить, получить три подписанных аудио.
5. Оценить отдельно сходство голоса, точность перевода и произношение.
6. Повторить для одного языка. После отмены старая кнопка не создаёт аудио.
7. После успешной дозагрузки `python parse_voices.py --download` перезапустить бота и проверить остальные записи.

# Проверка реализации

Дата: 09.11.2026.

## Выполнено

- Компиляция всех модулей Python: успешно.
- `python -m pytest -q`: **23 теста пройдены**.
- Реальное преобразование тестового WAV через FFmpeg в WAV 24 кГц mono PCM16 и MP3: успешно.
- Проверка слишком длинного аудио и неаудиофайла: успешно.
- Обработка Telegram updates через настоящий Dispatcher aiogram с подставным Telegram transport: успешно.
- Подтверждение перевода до синтеза и отклонение повторного нажатия старой кнопки: успешно.
- Полный сценарий создания голоса с подставным Google API: две записи, подтверждение, сохранение, выбор и очистка временных файлов.
- При ошибке создания профиль не сохраняется и успех не объявляется.
- При ошибке удаления локальный профиль сохраняется для повторной попытки.
- Изоляция голосов разных пользователей и запрет запросов неразрешённому пользователю: успешно.
- Сохранность настроек и незавершённой сессии после повторного открытия базы: успешно.
- Локальные дневные ограничения, ограничение истории и её очистка: успешно.
- Текущий формат REST-запросов, разбор аудио, скрытие внутренних thought-частей, отсутствие ключа в URL: проверены с httpx.MockTransport.
- Ошибки 400/401/403/404/429/500 и таймаут: проверены. Платные POST-запросы автоматически не дублируются.

## Среда локальной проверки

- Linux, Python 3.12.14.
- aiogram 3.31.0; httpx 0.28.1; python-dotenv 1.2.4; imageio-ffmpeg 0.8.1.
- pytest 9.2.0; pytest-asyncio 1.4.1.post1.

## Не проверено в этой среде

- Реальная авторизация и вызовы Google с ключом пользователя: ключ не предоставлялся.
- Реальная авторизация Telegram в новой реализации: токен из скриншотов не использовался.
- Наличие Paid Tier, квот, разрешений и доступности моделей в конкретном Google-проекте.
- Сходство клона, качество речи и распознавания на RU/KK/EN: необходимы реальные образцы и прослушивание.
- Запуск BAT-файлов на Windows/Python 3.13.7: инструкции подготовлены, но эта среда Linux.
- Сборка Docker-образа, развёртывание на сервере, непрерывная работа и нагрузочное тестирование.

Это проверенная локально реализация, готовая к настройке и живой приёмке. Эти результаты не означают, что внешние API и все голосовые функции уже проверены на аккаунте пользователя. Список приёмочных шагов находится в README_RU.md.

## Повторить тесты

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Тесты не обращаются к настоящим Telegram/Google endpoints и не расходуют платную квоту. Тестовые токены и ответы вымышлены; аудио для проверки конвертера — синусоидальный сигнал.
