# Shensheishi — Telegram-бот с голосами

## Обновление 16.11.2026: три языка и парсинг записей

- **«🌐 Текст на 3 языках»**: выбери сохранённый голос, отправь текст, затем нажми «Қазақша», «Русский», «English» или «Все три языка». После показа переводов и подтверждения бот создаст один или три аудиофайла. Голос фиксируется при получении текста и одинаков для всей серии.
- **«🎧 Известные люди: записи»**: 20 исходных записей публичных людей из Wikimedia Commons / BBC voice project. Есть прослушивание оригинала, автор, язык, источник и лицензия. Это зарубежная подборка; казахстанские люди в неё пока не входят.

**Озвучка нового текста голосами этих 20 людей не подключена.** Парсер собирает исходные записи, но не создаёт голосовые профили. Текущий Gemini Developer API требует отдельную настоящую запись согласия того же говорящего. В скачанных материалах её нет. Открытая лицензия на файл сама по себе не выполняет эту техническую проверку Google. Для синтеза доступны собственные успешно созданные профили и готовые голоса Google.

### Обновить существующий проект на Windows

1. Останови бота через Ctrl+C. Скопируй текущую папку проекта в резервную папку.
2. Распакуй новую папку `shensheishi` отдельно от старой.
3. Скопируй из старой папки `.env` и всю папку `data` в новую. Если в `.env` настроен другой `DATA_DIR`, перенеси именно эти данные. Сохрани прежний Google-проект: его голосовые ID принадлежат ему.
4. Запусти `install.bat`, затем `start.bat` в новой папке. Одновременно должен работать только один экземпляр бота.
5. Отправь `/start`. Проверь прослушивание в новом разделе записей; запросы к Google для него не нужны.
6. В «Мои голоса» выбери профиль. Открой «Текст на 3 языках», введи короткий текст, нажми «Все три языка» и подтверди переводы.

Серия на трёх языках использует до **6 запросов Google**: 3 перевода и 3 синтеза. При ошибке используй кнопку «Продолжить» или `/continue`. Успешные переводы и отправленные языки не повторяются; созданный MP3 после ошибки отправки используется повторно. При таймауте Google до получения ответа запрос мог выполниться на сервере, поэтому повтор может стоить ещё один запрос. При неопределённом результате отправки Telegram сообщение может дублироваться, но сохранённый MP3 не синтезируется повторно. `/cancel` удаляет временные файлы серии.

### Повторить парсинг

После активации `.venv` из папки проекта:

```bat
python parse_voices.py --download
```

Парсер читает `catalog/people_seed.json`, запрашивает официальный MediaWiki API (`imageinfo`, по 5 файлов), извлекает сведения об авторе, лицензии, длительности и ссылках. Затем скачивает файлы, проверяет размер и SHA-1 оригинала, преобразует полные записи в MP3 для Telegram. Результат: `catalog/people.json` и `catalog/samples`.

Повторный запуск использует проверенные скачанные файлы. При HTTP 429 учитывается пауза сервера; если ожидание превышает минуту, программа сообщает об этом и завершается. Старый каталог остаётся до успешного завершения обновления. Интервьюер, музыка и шумы оригинала автоматически не удаляются. Для бота перезапусти `start.bat` после обновления каталога.

Без `--download` обновляются метаданные и сохраняются ссылки на уже скачанные проверенные MP3. Остальные записи доступны через источник. Токены Telegram и Google для парсинга не нужны. Атрибуция аудиозаписей находится в `catalog/ATTRIBUTION.md`.

В поставку включены метаданные всех 20 людей и 10 MP3 для локального прослушивания. При загрузке остальных Wikimedia ответила HTTP 429 с паузой 600 секунд. Все 20 карточек имеют ссылку на страницу с проигрывателем оригинала. Позже выполни `python parse_voices.py --download`, чтобы дозагрузить оставшиеся MP3, затем перезапусти бота.

### Разобрать код для защиты

- `parse_voices.py`: запуск сбора и обработка ограничения частоты.
- `app/sources.py`: запросы к Commons, разбор метаданных, проверка скачивания.
- `app/multilingual.py`: выбор языка, переводы, подтверждение, продолжение после сбоя.
- `catalog/people_seed.json`: исходный список; `catalog/people.json`: результат парсинга.

Корректное описание: «Я реализовал сбор открытых аудиозаписей 20 публичных людей и каталог оригиналов. Отдельно реализовал многоязычную озвучку готовыми и сохранёнными профилями. Создание клонов публичных людей из скачанных записей в этой версии не подключено».

Источники: [Voice Intro Project](https://commons.wikimedia.org/wiki/Commons:Voice_intro_project/en), [BBC voice samples](https://commons.wikimedia.org/wiki/Category:BBC_voice_samples), [MediaWiki imageinfo](https://www.mediawiki.org/wiki/API:Imageinfo), [Google Voice replication](https://ai.google.dev/gemini-api/docs/voice-replication).

Здесь находится реализация Telegram-бота на Python и Gemini Developer API. Вместо обучения моделей с нуля бот использует готовые сервисы Google. Основные сценарии реализованы, но для использования нужно заполнить ключи, настроить доступ и выполнить приёмочные проверки ниже. Архив не содержит ваших токенов и личных записей.

## Что реализовано

| Функция | Поведение |
|---|---|
| Добавить голос | Имя, язык образца RU/KK/EN, образец речи, отдельная запись согласия, подтверждение, запрос к Google, сохранение voice ID |
| Мои голоса | Раздельные профили пользователей, выбор голоса, прослушивание, удаление из Google и локальной базы |
| Озвучить текст | Чтение исходного текста выбранным голосом, без автоматического перевода |
| Перевести и озвучить | Перевод на русский, казахский или английский, показ перевода, озвучка только после подтверждения |
| Поговорить с ИИ | Вопрос текстом или аудио, распознавание, ответ текстом и синтезированным голосом |
| Каталог | 30 стандартных голосов Google, страницы каталога и прослушивание |
| Настройки | Язык ответа, выбранный голос, дневной счётчик, очистка контекста |
| Надёжность | SQLite, сохранение состояния между запусками, лимиты, один активный запрос на пользователя, защита от двух локальных запусков, обработка сетевых ошибок |

«Добавить голос» создаёт профиль на стороне Google. Бот хранит voice ID и метаданные, а не веса обученной нейросети. Язык образца и язык синтеза независимы. Сходство, акцент и произношение требуют проверки на каждой паре голос/язык.

Каталог содержит стандартные голоса Google, не голоса знаменитостей. Для клонирования нужен образец взрослого владельца голоса и его собственная запись согласия. Скачанное интервью не заменяет эту запись. В этой версии используется русская фраза согласия из документации Google; образец речи можно записать на RU, KK или EN.

## Быстрый запуск на Windows

1. Остановите старого бота сочетанием Ctrl+C.
2. Распакуйте архив. Внутри находится папка `shensheishi`. Можно использовать её отдельно от старого проекта, чтобы сохранить старые файлы.
3. Запустите `install.bat`. Он создаст `.venv`, установит зависимости и создаст `.env`, только если такого файла ещё нет. Подходит установленный у вас Python 3.13.7.
4. Откройте `.env` в VS Code. Вставьте актуальный токен BotFather в `TELEGRAM_BOT_TOKEN`. Не вставляйте токен в Python-код.
5. Получите Gemini API key в Google AI Studio: https://aistudio.google.com/apikey . Запишите его в `GEMINI_API_KEY`.
6. Запустите `start.bat`. Отправьте своему боту `/id`.
7. Скопируйте только числовой ID пользователя в `ALLOWED_USER_IDS` в `.env`. Для нескольких участников укажите ID через запятую. ID бота из его токена не подходит: здесь нужен ваш пользовательский ID, который вернул `/id`.
8. Сохраните `.env`, остановите бота через Ctrl+C и снова запустите `start.bat`.
9. Отправьте `/start`, затем `/check`. Проверка `/check` читает сведения о моделях, но не проверяет создание голоса и не гарантирует наличие квоты на генерацию.
10. Откройте «Каталог голосов» → Kore → «Послушать». Затем выполните приёмочные проверки ниже.

Если `py` не находится, установите Python 3.11+ с официального python.org. Не запускайте `bot.py` из старого урока: точка входа нового проекта — `telegram_bot.py`.

Пример `.env` (значения впишите свои):

```dotenv
TELEGRAM_BOT_TOKEN=ваш_актуальный_токен
GEMINI_API_KEY=ваш_ключ_google
ALLOWED_USER_IDS=ваш_числовой_ID
GEMINI_TEXT_MODEL=gemini-3.8-flash
GEMINI_TTS_MODEL=gemini-3.8-flash-tts
```

Не заменяйте остальные имена переменных в `.env.example`. `ALLOWED_USER_IDS` с пустым значением закрывает голосовые функции для всех: остаётся доступной команда `/id`. Это позволяет подключить ключ и не открыть расход квоты всем пользователям Telegram.

Ручная установка вместо BAT-файлов, из папки проекта в CMD:

```bat
py -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
copy .env.example .env
python telegram_bot.py
```

Команду `copy` выполняйте только если `.env` ещё не существует. Если Windows скрывает расширения, убедитесь, что имя файла — `.env`, а не `.env.txt`.

## Google: ключ, оплата и ограничения

- Используется Gemini Developer API с ключом из AI Studio, не сервисный аккаунт Vertex AI.
- Согласно проверенной документации Google на 09.11.2026, создание голосового клона требует проекта Paid Tier (Tier 1+). Наличие бесплатного API-ключа само по себе этого доступа не даёт. Подключение оплаты и тариф проверяйте в своём проекте; проект ничего не покупает автоматически.
- Модели задаются в `.env`. Если Google изменит доступность модели, нужно выбрать доступную совместимую модель и повторить проверки; изменение имени само по себе не добавляет поддержку клонирования.
- Бот ограничивает число запросов, но это не денежный бюджет: стоимость зависит от длины текста и аудио. Контролируйте биллинг Google отдельно.
- Сохранённые профили Google имеют квоты и срок хранения. В текущей документации указан лимит 200 голосов на проект и срок 1 год с последнего использования. Бот дополнительно ограничивает число голосов одного пользователя.
- При 403 проверяйте доступ/ключ/оплату; при 429 — квоты; при 404 — модель, срок хранения и наличие профиля; при 5xx — состояние сервиса.
- Если запрос создания завершился таймаутом, профиль мог быть создан у Google. Перед повтором проверьте список голосов в AI Studio, чтобы не создать дубликат. Автоматического повтора такой операции в боте нет.

## Запись нового голоса

1. «Добавить голос» → подтверждение использования своего голоса или согласия взрослого владельца.
2. Дайте короткое имя и выберите язык образца.
3. Отправьте 10–30 секунд чистой речи без музыки, эха и других говорящих. Поддерживаются голосовые Telegram и WAV/MP3/OGG/M4A/FLAC/WebM.
4. Тот же человек записывает фразу согласия, которую покажет бот. Её нужно прочитать дословно. Бот преобразует записи в WAV 24 кГц, mono, PCM16; отдельная установка FFmpeg обычно не нужна, исполняемый файл приходит с imageio-ffmpeg.
5. Нажмите «Создать голос». Только успешный ответ Google приводит к сохранению профиля. Выбранный язык хранится как язык образца, а не ограничение для синтеза.
6. Откройте «Озвучить текст», выберите язык и отправьте подходящий текст. Повторите для RU, KK и EN.

После успешного создания исходные файлы удаляются локально. Временные незавершённые записи очищаются примерно через 24 часа: при запущенном боте очистка идёт раз в час, после остановки — при следующем запуске. Можно удалить их сразу через `/cancel`. Входные записи также проходят через Telegram и Google; локальная очистка не является удалением всех копий у внешних сервисов.

## Что сохраняется

В папке `data` находятся SQLite-база и временные записи незавершённого создания голоса. В базе — настройки, ID профилей, язык образца, время создания, последние 6 пар реплик диалога, счётчики и Telegram file ID коротких примеров. Записи вопросов и файлы ответов обрабатываются во временных папках и удаляются после обработки.

Каждый callback с пользовательским голосом повторно проверяет его владельца. Общий Google-проект не делает личные голоса доступными другим пользователям бота. Администратор проекта и владелец сервера всё равно имеют доступ к своей инфраструктуре.

Для очистки диалога используйте `/newchat`. Для удаления клона — «Мои голоса» → «Удалить» → подтверждение. Бот удаляет профиль Google, затем запись базы. Если Google не подтвердил удаление, запись сохраняется для повтора. Сами сообщения в Telegram этим действием не удаляются.

## Приёмочные проверки перед использованием

Выполните их на своём аккаунте. Локальные автоматические тесты не заменяют реальные запросы к Telegram и Google.

| Проверка | Ожидаемый результат |
|---|---|
| `/start`, `/check` | Меню открывается, ключ позволяет прочитать выбранные модели |
| Каталог → прослушивание | Приходит новое синтезированное аудио, затем работает выбор голоса |
| RU/KK/EN | Каждый тестовый текст озвучивается; слушатель оценивает понятность и произношение |
| Перевод | До нажатия подтверждения аудио не создаётся; после — приходит озвученный перевод |
| Текстовый вопрос | Приходят осмысленный текст и соответствующая озвучка |
| Голосовой вопрос | Показана расшифровка, затем ответ и озвучка |
| Новый профиль | Образец + согласие принимаются Google, профиль появляется в «Мои голоса» |
| Клон на трёх языках | Проверены читаемость, сходство и акцент; одинаковое качество не предполагается заранее |
| Перезапуск | Сохранённые голоса и язык остаются доступны |
| Второй разрешённый пользователь | Не видит и не может выбирать чужой профиль |
| Удаление | Профиль исчезает из Google и бота; при удалении выбранного профиля выбран Kore |
| Отмена | `/cancel` очищает незавершённую запись и возвращает меню |
| Лимиты и сбой | При ошибке появляется понятное сообщение, успех не подменяется исходной записью |

Дополнительная диагностика:

```bat
.venv\Scripts\python.exe doctor.py
```

Без флага это проверки соединений и доступности моделей. Команда ниже **делает три коротких запроса синтеза**, расходует квоту/средства Google и сохраняет файлы в `data/checks`:

```bat
.venv\Scripts\python.exe doctor.py --tts
```

Выполненные в среде разработки проверки описаны в `VERIFICATION.md`.

## Постоянная работа

На ноутбуке бот отвечает только пока работает Python, компьютер не спит и есть интернет. Для круглосуточного использования перенесите проект на Linux-сервер с Docker. Сервер должен иметь исходящий HTTPS-доступ к Telegram и Google. Открывать входящий HTTP-порт для polling не нужно.

На сервере заполните `.env`, затем:

```bash
docker compose up -d --build
docker compose logs -f --tail=100
```

В комплекте есть `Dockerfile` и `compose.yaml`. Контейнер работает без root, база находится в постоянном named volume, включён перезапуск. Остановите локальный экземпляр: один Telegram-токен должен обслуживаться одним polling-процессом. `docker compose down -v` удаляет данные — не используйте эту команду для обычного перезапуска.

Docker-конфигурация подготовлена, но развёртывание на вашем сервере и проверка непрерывной работы в этом сеансе не выполнялись. Для обновления и резервного копирования сначала остановите бота, затем сохраните всю папку данных/volume, включая файлы SQLite.

## Как устроен код

| Файл | Назначение |
|---|---|
| `telegram_bot.py` | Запуск, настройки команд, подключение Telegram, остановка, защита от второго процесса |
| `app/bot.py` | Сценарии меню, шаги диалога, доступ, владение голосами, лимиты и обработка ошибок |
| `app/gemini.py` | HTTPS-запросы к официальным Gemini endpoints, разбор ответов |
| `app/storage.py` | SQLite: пользователи, профили, сессии, история, счётчики |
| `app/audio.py` | Проверка длительности и преобразование входных записей/выходного звука |
| `app/ui.py` | Кнопки, языки и готовые голоса |
| `app/config.py` | Чтение `.env` и проверка настроек |
| `doctor.py` | Диагностика подключения без печати ключей |
| `tests/` | Локальные проверки сценариев, изоляции, API-контракта и FFmpeg |

Сначала разберите `telegram_bot.py` и `app/ui.py`, затем `on_message` и `on_callback` в `app/bot.py`. На защите корректно говорить: «Я реализовал Telegram-бота и полный прикладной конвейер обработки речи, используя готовые API Google». В приложенном ранее плане упоминалось локальное обучение без API; это описание не соответствует данной реализации.
